# دستورالعمل قطعی

وقتی مسیر می‌میرد، اول باید بفهمی **کدام** مسیر مرده. سه حالت کاملاً متفاوت
شبیه هم به نظر می‌رسند و درمانشان یکی نیست.

## گام ۰ — تشخیص

از **سرور ایران**:

```bash
# آیا مسیر بین‌الملل اصلاً هست؟
ping -c3 8.8.8.8
curl -sS --max-time 5 -o /dev/null -w '%{http_code}\n' https://www.google.com

# آیا فقط سرور خارج ما رفته؟
timeout 5 bash -c 'exec 3<>/dev/tcp/<kharej-ip>/443' && echo reachable || echo blocked

# سرویس‌های داخلی؟
curl -sS --max-time 5 -o /dev/null -w '%{http_code}\n' https://www.digikala.com
```

| نتیجه | تشخیص | برو به |
|---|---|---|
| همه‌چیز OK ولی تونل کند/ریست می‌شود | DPI روی الگو | گام ۱ |
| فقط IP سرور خارج جواب نمی‌دهد | بلاک L3 | گام ۲ |
| هیچ مقصد خارجی جواب نمی‌دهد، داخلی‌ها OK | نت ملی | گام ۳ |
| هیچ‌چیز جواب نمی‌دهد | قطعی کامل یا مشکل خود سرور | گام ۴ |

---

## گام ۱ — DPI: ترنسپورت را عوض کن

اتصال برقرار می‌شود ولی می‌میرد؟ چیزی که فیلتر می‌شود *شکل* ترافیک است، نه
آدرس. روی **سرور خارج**:

```bash
sudo sed -i 's/^transport = .*/transport = "stealth"/' /etc/backpack/main.toml
sudo systemctl restart backpack-main
journalctl -u backpack-main -f
```

روی **سرور ایران** هم همان را عوض کن — دو طرف باید یکی باشند:

```bash
sudo sed -i 's/^transport = .*/transport = "stealth"/' /etc/backpack/main.toml
sudo systemctl restart backpack-main
```

`stealth` روی سیم بایت تصادفی است — بدون handshake قابل‌تشخیص و بدون اثرانگشت
TLS. اگر جواب نداد، `wssmux` را روی پورت `443` امتحان کن: شکل ترافیک عین یک
سایت HTTPS معمولی می‌شود.

---

## گام ۲ — بلاک L3: آدرس را عوض کن

هیچ ابهام‌سازی‌ای یک IP بلاک‌شده را باز نمی‌کند. باید مقصد عوض شود.

**اگر IP سرور خارج بلاک شده:** مهم نیست. جهت dial از خارج به ایران است، پس از
ایران هیچ بسته‌ای به آن آدرس نمی‌رود. اگر با این حال تونل بالا نمی‌آید، مشکل
گام ۱ است نه اینجا.

**اگر IP سرور ایران بلاک شده** (سمت خارج نمی‌تواند dial کند): آدرس پشتیبان را
فعال کن. اگر watchdog نصب باشد این خودکار انجام می‌شود:

```bash
journalctl -u paket-route-health -n 30      # ببین چه دید
paket-route-health --dry-run                # الان چه چیزی زنده است
```

دستی:

```bash
sudo sed -i 's|^remote_addr = .*|remote_addr = "<آدرس تمیز>:443"|' /etc/backpack/main.toml
sudo systemctl restart backpack-main
```

**اگر آدرس تمیزی نداری:** برو پشت CDN. دامنه را روی CDN بیاور، origin را سرور
ایران بگذار، و سمت خارج به لبه وصل شود:

```bash
sudo sed -i 's|^edge_ip = .*|edge_ip = "<CDN-edge-ip>"|' /etc/backpack/main.toml
sudo sed -i 's/^transport = .*/transport = "wssmux"/' /etc/backpack/main.toml
sudo systemctl restart backpack-main
```

CDN فقط `wss` و `wssmux` را روی پورت‌های پراکسی‌شده (`443`، `8443`، `2053`، …)
عبور می‌دهد. ترنسپورت خام از CDN رد نمی‌شود.

---

## گام ۳ — نت ملی

مسیر بین‌الملل قطع است. هیچ تنظیمی روی BackPack این را حل نمی‌کند — تا وقتی
مسیر برنگردد، تونل برنمی‌گردد.

کاری که *می‌شود* کرد:

```bash
# روی سرور ایران — کانال DNS باید هنوز کار کند
systemctl status paket-dnstt
ssh -p 7000 root@127.0.0.1
```

از داخل آن شل روی سرور خارج، آماده‌سازی برای لحظه‌ی برگشت:

- کانفیگ را روی `stealth` یا `wssmux` بگذار (وقتی مسیر برگردد، معمولاً با DPI
  سفت‌تری برمی‌گردد)
- آدرس ذخیره را به `fallback_addrs` اضافه کن
- لاگ‌ها را نگاه کن تا بفهمی دقیقاً کِی و چطور مرد

اگر کانال DNS هم مرده، تنها چیزی که باقی می‌ماند رسانه‌ی فیزیکی دیگری است:
سیم‌کارت رومینگ خارجی روی مودم LTE، یا Starlink. اگر uptime برایت حیاتی است،
یکی از این‌ها باید از قبل در نقشه باشد — نه بعد از قطعی.

---

## گام ۴ — هیچ‌چیز جواب نمی‌دهد

قبل از فرض قطعی سراسری، مطمئن شو مشکل خود سرور نیست:

```bash
systemctl status backpack-main paket-dnstt
ip route
journalctl -u backpack-main --since '30 min ago' | tail -50
df -h /            # دیسک پر هم دقیقاً همین شکلی به نظر می‌رسد
```

---

## بعد از اینکه برگشت

قطعی تمام شد؟ چند دقیقه وقت بگذار:

1. **ببین کدام مسیر زنده ماند.** `journalctl -u paket-route-health --since '1 day ago'`
   دقیقاً می‌گوید چه چیزی چه زمانی مرد. این ارزشمندترین دیتای توست.
2. **آدرس سوخته را دور بینداز**، جایش یکی تازه بگیر و به `fallback_addrs` اضافه کن.
3. **ترنسپورتی که جواب داد را نگه دار** — به حالت قبلی برنگرد.
4. **کانال DNS را تست کن.** اگر لازم شد و کار نکرد، الان وقت درست‌کردنش است.

## چک‌لیست پیش از قطعی بعدی

- [ ] حداقل یک آدرس ذخیره در `fallback_addrs` که تا حالا استفاده نشده
- [ ] کانال DNS بالا و **تست‌شده**
- [ ] watchdog نصب و در حال لاگ‌گرفتن
- [ ] بکاپ کانفیگ جایی بیرون از هر دو سرور
- [ ] دسترسی به پنل DNS دامنه از داخل ایران (اگر پنل فیلتر باشد، وسط قطعی
      نمی‌توانی رکورد عوض کنی)

آخری بیشتر از چیزی که فکر می‌کنی آدم‌ها را زمین می‌زند.
