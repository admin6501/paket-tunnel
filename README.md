# paket-tunnel

کیت راه‌اندازی یک مسیر تونل مقاوم بین **سرور ایران** و **سرور خارج**، ساخته‌شده
روی [BackPack](https://github.com/AminMGMT/BackPack) به‌عنوان موتور انتقال.

این ریپو خودش یک موتور تونل جدید نیست. کاری که می‌کند این است که BackPack را در
یک معماری **سه‌لایه** می‌چیند تا وقتی مسیر اصلی می‌میرد — چه با فیلتر شدن IP، چه
با DPI، چه با قطعی سراسری — یک لایه‌ی پایین‌تر هنوز زنده باشد و بتوانی از راه دور
سرور را برگردانی.

---

## مسئله

سه اتفاق متفاوت را معمولاً همه «فیلتر شد» صدا می‌زنند، در حالی که درمانشان فرق دارد:

| اتفاق | نشانه | درمان |
|---|---|---|
| DPI روی الگوی ترافیک | اتصال برقرار می‌شود ولی ریست/کند می‌شود | ترنسپورت مبهم: `stealth` یا `wss` |
| بلاک لایه‌ی ۳ روی IP | اصلاً چیزی وصل نمی‌شود | IP تمیز، یا رفتن پشت CDN |
| قطعی سراسری (نت ملی) | مسیر بین‌الملل صفر | کانال کم‌پهنا (DNS) یا رسانه‌ی فیزیکی دیگر |

هیچ ترنسپورتی نمی‌تواند یک IP بلاک‌شده‌ی L3 را باز کند و هیچ نرم‌افزاری روی مسیری
که صفر بیت عبور می‌دهد تونل نمی‌زند. هر چیزی که اینجا ساخته شده، دور همین دو
محدودیت طراحی شده، نه در انکار آن‌ها.

## معماری

```
                 ┌─ لایه ۲: کانال کنترلی (DNS) ─── همیشه آخرین چیزی که می‌میرد
                 │
کاربر ──▶ سرور ایران ◀══ لایه ۰: تونل اصلی ══ سرور خارج ──▶ اینترنت آزاد
                 │        (WSS Mux پشت CDN)
                 └─ لایه ۱: مسیر پشتیبان (stealth روی IP ذخیره)
```

نکته‌ی کلیدی جهت اتصال: **تونل همیشه از سمت خارج dial می‌شود.** سرور ایران نقش
`server` را دارد و سرور خارج نقش `client`. یعنی هیچ بسته‌ای از ایران به سمت IP
فیلترشده نمی‌رود و فیلترینگ مقصد دور می‌خورد. سرور خارج هم نیازی به پورت باز
ورودی ندارد.

جزئیات کامل: [`docs/architecture.md`](docs/architecture.md)

## نصب

روی **هر دو سرور** (Ubuntu/Debian، دسترسی root) یک خط:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/admin6501/paket-tunnel/main/install.sh)
```

ریپو را در `/opt/paket-tunnel` می‌گذارد، باینری BackPack مناسب معماری را نصب
می‌کند (از داخل خود ریپو، با تأیید چک‌سام — بدون دانلود) و دستور `paket-tunnel`
را اضافه می‌کند.

### نصب آفلاین

اگر سرور به گیت‌هاب نمی‌رسد، یک کلون که قبلاً گرفته‌ای کافی است — باینری‌ها
داخل ریپو هستند:

```bash
git clone https://github.com/admin6501/paket-tunnel.git
cd paket-tunnel && sudo ./install.sh --offline
```

## راه‌اندازی

```bash
sudo paket-tunnel
```

منوی تعاملی باز می‌شود؛ همه‌چیز از همان‌جا انتخاب می‌شود — نقش سرور، ترنسپورت،
پورت‌ها، آدرس‌های پشتیبان، لبه‌ی CDN. لازم نیست هیچ فلگی حفظ کنی.

```
 1) راه‌اندازی سرور ایران   (نقش server — اول این)
 2) راه‌اندازی سرور خارج    (نقش client — بعد از ایران)

 3) تغییر ترنسپورت
 4) آدرس‌های پشتیبان
 5) کانال کنترلی DNS
 6) نگهبان مسیر

 7) وضعیت
 8) لاگ زنده
 9) کنترل سرویس

10) بکاپ و بازیابی
11) بهینه‌سازی شبکه
12) راهنما
13) منوی خود backpack
```

**اول گزینه‌ی ۱ روی سرور ایران، بعد گزینه‌ی ۲ روی سرور خارج** — چون سمت خارج به
آی‌پی و توکنی که سمت ایران چاپ می‌کند نیاز دارد.

هنگام انتخاب ترنسپورت، کنار هر گزینه نوشته شده روی سیم چه شکلی است و کِی به
دردت می‌خورد، پس لازم نیست از قبل بدانی کدام را می‌خواهی.

### بدون منو

همان کارها با فلگ، برای اسکریپت‌نویسی:

```bash
sudo paket-tunnel iran   --ports "443=127.0.0.1:8080" --transport wssmux
sudo paket-tunnel kharej --server 1.2.3.4:443 --token <token> --backup 5.6.7.8:8443
sudo paket-tunnel watchdog
sudo paket-tunnel status
sudo paket-tunnel logs [name]
sudo paket-tunnel update
```

`--help` روی هر زیردستور گزینه‌هایش را نشان می‌دهد.

### نگاشت پورت‌ها

سمت ایران تعریف می‌شود، نه سمت خارج: `443=127.0.0.1:8080` یعنی کاربر به پورت
۴۴۳ سرور ایران وصل می‌شود و ترافیکش روی سرور خارج به `127.0.0.1:8080` تحویل
داده می‌شود.

## ساختار

```
install.sh         نصب تک‌خطی (آنلاین و آفلاین)
menu/              منوی تعاملی
bin/               باینری آماده‌ی BackPack (amd64/arm64) + نصب آفلاین
deploy/            اسکریپت‌های نصب و ساخت کانفیگ برای هر دو نقش
configs/           نمونه‌کانفیگ TOML (wssmux پشت CDN، stealth، kcp)
control-channel/   تونل DNS به‌عنوان کانال کنترلی اضطراری
watchdog/          سلامت‌سنجی و چرخش خودکار مسیر
docs/              معماری و دستورالعمل قطعی
```

## پیش‌نیاز و محدودیت‌ها

- باینری BackPack داخل `bin/` هست؛ نصب کاملاً آفلاین انجام می‌شود. اگر نبود،
  `deploy/` سراغ نصب‌کننده‌ی بالادست می‌رود که به گیت‌هاب نیاز دارد.
- برای `wss`/`wssmux` پشت CDN، یک دامنه لازم است که رکوردش به سرور ایران بخورد و
  پورت از پورت‌های پراکسی‌شده‌ی CDN باشد (`443`, `8443`, `2053`, …).
- برای کانال DNS، یک دامنه با دسترسی به رکوردهای `NS` لازم است.
- BackPack از هاپ سوم عبور نمی‌دهد؛ اگر هر دو سر کاملاً بلاک باشند و CDN هم در
  کار نباشد، به یک آدرس تمیز نیاز داری.
